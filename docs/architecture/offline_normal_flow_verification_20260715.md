# 正常赛道主流程离线整改与验证报告

日期：2026-07-15

## 本轮范围

本轮只处理正常赛道流程。障碍识别、颜色牌识别、方向牌识别均不进入生产运行；环岛左右方向来自固定配置，不是在线识别结果。

当前有效赛道顺序为：

`corner → ring_entry → ring_exit → finished`

岔路、返回及其方向选择暂不属于当前运行状态图。环岛出口完成后进入 `finished`，最终命令固定为零。

## 当前每帧执行链

每一帧只经过以下一条链路：

1. 相机读取一帧。
2. 普通黑线视觉生成基础轨迹。
3. 只调用当前赛道阶段的检测器与执行器。
4. 当前阶段产生唯一候选命令及唯一控制权所有者。
5. 唯一命令仲裁器检查命令并产生最终命令。
6. 电机网关只接收该最终命令。

生产 Runner 不再提供切回旧全局检测器的配置开关，旧的并行 Runner 分支也已删除。阶段切换统一经过：零命令、确认静止、销毁旧阶段、初始化新阶段、切换控制权、从零斜坡恢复。

## 阶段隔离结论

- `corner`：只启用直角检测与直角执行器。
- `ring_entry`：只启用环岛入口几何与环岛执行器。
- `ring_exit`：只启用环岛出口几何与同一条已锁定环岛路线。
- `finished`：无检测器、无运动执行器，锁定完成停车。

阶段、候选命令来源和控制权所有者在单帧结果中有一致性断言；不一致会直接报错，不能静默输出到电机。

## 本机图像处理与延迟

在本机用 96 张已有正式运行录制帧，通过生产 `FixedCourseFramePipeline` 重放：

| 项目 | 平均 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| 普通视觉 | 3.975 ms | 4.922 ms | 7.339 ms |
| 当前阶段处理 | 6.573 ms | 26.047 ms | 29.207 ms |
| 命令仲裁 | 0.003 ms | 0.004 ms | 0.006 ms |
| 单帧总处理 | 10.551 ms | 30.791 ms | 33.272 ms |

目标周期为 75 ms，本次重放超期 0 帧。

分阶段 ROI 优化以原公共 ROI 为基准，只裁掉原本已经不参与有效判断的区域。96 帧等价测试中，几何类别、方向、端点数、分叉标志、角度、入口误差和顶点物理位置均保持一致，没有发现因优化导致的检测失效。

障碍检测模块、配置、页面开关、每帧处理、遥测字段和调试图输出均已移除，因此它不再占用正常流程的视觉延迟。项目中没有独立的颜色牌或方向牌识别主流程。

## 树莓派实际离线延迟

通过 SSH 在真实 aarch64 机器上，用远端已有 JPEG 文件离线测试。没有启动 Runner、没有打开摄像头，也没有调用 `VideoCapture`。测试环境为 Python 3.11.2、OpenCV 4.9.0、`ondemand` governor；测试时 CPU 频率 1.6 GHz、上限 2.4 GHz、温度约 66.1°C。

测试使用与本机完全相同的 96 张图片，首帧 SHA-256 一致。当前生产管线连续运行三轮，结果为：

| 项目 | 三轮平均值范围 | 三轮 P95 范围 |
| --- | ---: | ---: |
| 普通视觉 | 11.491–11.740 ms | 15.355–15.806 ms |
| 当前阶段处理 | 32.451–33.290 ms | 128.971–131.396 ms |
| 命令仲裁 | 0.015 ms | 0.017–0.018 ms |
| 单帧总处理 | 43.957–45.045 ms | 139.534–143.358 ms |

三轮中位结果为：平均 44.000 ms、P95 139.841 ms、最大值约 149.160 ms。每轮都有 25/96 帧超过 75 ms。因此树莓派上的普通帧足够快，但执行几何分析的帧仍明显超期；不能根据本机 0 超期得出树莓派已达到实时目标的结论。

JPEG 文件读取和解码另测 288 次：平均 4.279 ms、P95 4.523 ms、最大 5.217 ms。上表为与此前基准一致的纯生产管线耗时，不包含这部分离线文件解码时间。

远端覆盖当前代码前，使用旧版代码对同一组图片执行“普通视觉 + 障碍识别 + 几何识别全部逐帧开启”基准：平均 156.960 ms、P95 275.387 ms、最大 426.913 ms。与这个旧识别全开基准相比，当前生产管线平均降低约 72%，P95 降低约 49%。该旧数字是识别全开压力基准，不等同于旧 Runner 动态门控后的生产平均值。

## 离线验证结果

- 全量测试：205 passed，13 subtests passed。
- 正式录制帧生产管线回放通过。
- 环岛路线身份锁定、短时缺帧记忆和路线丢失锁测试通过。
- 阶段切换静止屏障及斜坡测试通过。
- 生产管线的“一个候选来源、一个控制权所有者、一次仲裁”断言通过。
- `git diff --check` 无格式错误。

## 仍需真车验证

离线结果不能替代以下硬件事实：

1. 将树莓派几何帧的 P95 从约 140 ms 降到 75 ms 周期以内。
2. 摄像头真实采集阻塞；本轮按要求完全没有调用相机。
3. 直角完成后到环岛入口、环岛出口再到完成停车的整段连续实车运行。
4. 轮速/里程反馈的新鲜度、静止确认和切换斜坡在底盘上的实际表现。
5. 光照、反光、车体遮挡、运动模糊下的几何稳定性。

因此当前结论是：离线架构已经是清晰的线性状态，未发现互相抢控制权的并行逻辑；视觉优化在已有录制数据上保持等价，并且显著快于旧识别全开基准。但真实树莓派的几何帧仍会超出 75 ms，性能工作尚未完成。是否能在真实赛道连续完成全程，仍必须由一次新的真车正式运行确认。
